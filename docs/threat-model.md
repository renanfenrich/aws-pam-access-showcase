# Threat model

The protected assets are the target credential, JumpServer policy/session data, VPN CA/client material, Terraform state, deployment authority, and audit evidence. The model assumes one AWS account and trusted account administrators.

| Threat | Trust boundary | Preventive control | Detective control | Residual risk | Recovery action |
| --- | --- | --- | --- | --- | --- |
| Stolen VPN profile | Workstation → OpenVPN | Per-client certificate, explicit operator CIDR, route only JumpServer `/32`, no target SG path | VPN logs, unexpected source/login attempts | Attacker can reach private JumpServer ports from the allowed source | Revoke certificate, publish CRL, rotate profile, investigate source |
| Stolen JumpServer credentials | Operator → JumpServer | Forced MFA, expiring one-user authorization, no direct target route | Failed-login, MFA, session, and command audit | MFA phishing or active browser theft | Disable user/authorization, revoke sessions, rotate password, review recordings |
| Compromised GitHub workflow | GitHub OIDC → AWS | Exact repo/environment subjects, approvals, exact-main commit, separate roles, no static keys | CloudTrail role sessions, protected-environment history, plan/evidence | Approved malicious code can use role permissions | Disable environments/roles, revoke sessions, inspect CloudTrail, restore reviewed commit |
| Compromised dependency action | Marketplace action → runner | Full commit SHAs, minimal permissions, actionlint, zizmor, few actions | Dependabot review and workflow security scans | Pinned upstream commit could already be malicious | Remove action, rotate affected credentials, inspect run logs and CloudTrail |
| Compromised OpenVPN host | Public subnet → private access | No EC2 key, SSM admin, SG/host firewall denies target, pushed `/32` only | VPC Flow Logs, SSM inventory, network probe | Root could tamper with VPN sessions and attack JumpServer ports | Isolate/replace instance, revoke CA/client, inspect JumpServer and flow logs |
| Compromised JumpServer host | PAM boundary → target | Target permits only JumpServer SG, dedicated non-root key/account, no sudo | Target audit, JumpServer audit, VPC Flow Logs | Root on JumpServer can use brokered key and tamper with local recordings | Isolate host, rotate target key, rebuild, preserve external evidence |
| Compromised target account | JumpServer managed account → target OS | Password locked, dedicated key, no sudo, limited readable file | SSH/audit logs and JumpServer commands | Kernel/local privilege escalation remains possible | Disable account/key, isolate target, replace instance, review session |
| Terraform state leakage | Backend → reader | Versioned private S3, KMS, TLS-only policy, role-scoped access, no generated secrets | S3 data events where enabled, IAM/CloudTrail review | State reveals infrastructure identifiers and private topology | Revoke access, rotate exposed identifiers/credentials, recover known-good state |
| Secrets in Ansible logs | Controller/task → GitHub logs | `no_log`, secret-name-only inventory, sanitized output, cleanup | Gitleaks and manual log review | Module/runner defect or debugging can leak values | Delete logs where possible, rotate leaked secret, incident review |
| S3 transfer-object retention | Runner/instance → SSM bucket | Dedicated bucket, KMS, approved principals only, one-day lifecycle, no versioning | S3 inventory/access events and lifecycle checks | Object may persist until lifecycle execution | Delete prefix, revoke access, rotate material if exposed |
| Overly broad routes | VPN/VPC routing boundary | Fixed `/32` push, isolated no-default route, explicit return route only | Terraform tests, route inspection, VPC API evidence | Host compromise could change runtime routes | Stop VPN, restore Ansible config, replace host, review flows |
| Overly broad security groups | ENI boundary | Source-SG target SSH, VPN-CIDR JumpServer only, operator-CIDR UDP only | Native tests, Trivy, AWS API evidence | Account-level mutation outside Terraform | Revoke mutation authority, reconcile reviewed plan, investigate CloudTrail |
| Session-recording tampering | JumpServer host/storage → auditor | Encrypted volume and restricted admin path | Session/command consistency checks and evidence capture | Local admin can alter single-node storage | Preserve external evidence, rebuild; production requires immutable remote storage |
| Expired access not revoked | Time/authorization boundary | Required future expiration and JumpServer `date_expired` | API verification checks expiration | Clock/config defects or manual override | Disable permission/user, revoke sessions, reconcile policy |
| Failure to destroy chargeable resources | Workflow → AWS billing | Explicit expiration tags, budget, protected destroy, post-destroy tagged-resource scan | Budget alert and final verification artifact | Tagging API lag or unsupported resource type | Query service inventories/Cost Explorer, manually remove exact deployment resources |

The largest residual risk is the intentionally single JumpServer trust point. This is acceptable only for an ephemeral portfolio demonstration.
